# Quickstart

Add Quod to an existing GitHub Actions workflow. Your install and test commands stay exactly as they are.

## Prerequisites

- A test suite on **vitest 4.x**
- **Node 22.15 or later** (Quod uses `module.registerHooks`)
- A **Linux x64** runner, such as `ubuntu-latest`
- Your repository in a Quod team, with the Quod GitHub App installed on it. Quod is in early access: [join the waitlist](/#join) to get a team.

## Add Quod to your workflow

<Steps>

### Give the test job an OIDC token

Quod Cloud keeps the ledger of recorded results, and it identifies your job by its GitHub OIDC token. Add `id-token: write` to the job that runs your tests:

```yaml title=".github/workflows/ci.yml"
jobs:
  test:
    permissions:
      contents: read
      id-token: write
```

### Add the action after setup-node

Add one line right after `actions/setup-node`. From then on, every one-shot `vitest run` in the job goes through Quod, however it's started. Your dependencies are restored before your install step, and turbo's or Nx's remote cache points at Quod Cloud if you haven't set up one of your own.

```yaml title=".github/workflows/ci.yml" {5}
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: 24
      - uses: pango07/quod-action@991753ca6f46d81b184604673dfd247e66a9476e # v2
      - run: npm ci
      - run: npm test
```

<Tip>
  Pin the full commit SHA with `# v2` as a comment, as shown. GitHub recommends this for third-party actions, and Dependabot and Renovate keep such pins up to date. `@v2` also works if your policy allows tags.
</Tip>

### Push

Commit the workflow and push. That's all: there's no second job. The test job records as it runs, and each record replays once a second run agrees with it.

</Steps>

</Tabs>

<Note>
  You don't need setup-node's `cache:` option. Quod restores `node_modules` for npm, and the package store for pnpm, yarn and bun. If you keep `cache:`, or another step restores your dependencies, Quod leaves what it restored alone. For pnpm and bun, put their setup step before the Quod line, as shown, so Quod can find the store.
</Note>

<Warning>
  Quod hooks vitest whenever vitest runs under Node. The npm setup runs at our first customer, a turbo monorepo, and our benchmarks run on pnpm projects (vuejs/core and vuejs/router). The yarn and bun setups follow the same rules, but they haven't been benchmarked yet. `bun test` is Bun's own test runner, not vitest, so Quod doesn't touch it.
</Warning>

## What you'll see

### The first run

There's no recording yet, so every test file runs at about plain vitest speed, and is recorded as it runs. The action's log says so:

```txt
Quod: no recording yet; every test file runs and records
```

### The second run

Each record from the first run is **provisional**: it replays only once a second, independent run of the same inputs gives the same per-test results. So the second run runs those files again, as their second witness:

```txt
quod vitest: second witness: 280 provisional records run again (2 witnesses needed)
```

### Every run after that

The test job reads the newest recording: the nearest recorded ancestor commit in Quod Cloud, else your branch, the pull request's base, then the default branch. Before vitest starts, Quod prints what it decided:

```txt
quod vitest: 280 recorded files: 274 replay, 6 to run; 3120 inputs hashed, 9 changed; selected in 140 ms
quod vitest:   runs: src/router.spec.ts <- f:src/router.ts
```

The `runs:` lines name, for up to 12 files, the first changed input that made each one run. vitest's own summary, reports and exit code look like a full run's, with the replayed files included. A file that ran because it changed is recorded again, and replays after the next run agrees with it.

<Note>
  The numbers in these logs are examples. The exact wording may change between releases.
</Note>

## Turn it off

Set `QUOD_DISABLE: 1` in the job's or workflow's `env` to get plain vitest. The action line can stay where it is.

```yaml title=".github/workflows/ci.yml"
env:
  QUOD_DISABLE: 1
```

To remove Quod completely, delete the action line. To turn off just one part, such as recording, the dependency cache or the turbo/Nx cache, see [the action's inputs](/docs/reference/action#turning-parts-off).

<Note>
  **Coming from v1?** Delete the `quod-shadow` job, and update the action line to v2. The first run or two after upgrading run every file while records collect their second witness. See [Troubleshooting](/docs/troubleshooting#every-file-ran-right-after-upgrading).
</Note>
